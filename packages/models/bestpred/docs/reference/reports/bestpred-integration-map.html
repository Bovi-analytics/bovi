BESTPRED integratiekaart

Visuele uitleg van de Fortran-oracle, de Python-port, Bovi core en farm-data-definitions. De kernregel: FDD beschrijft data, bestpred-py rekent, Bovi presenteert en integreert.

1. De drie systemen en hun verantwoordelijkheid

De huidige situatie is nog niet een nette keten. Fortran is de oracle, bestpred-py is de gecontroleerde port, FDD is de beoogde gedeelde datastructuur en Bovi heeft nu vooral een dataframe/melk-only API.

Oracle en legacy gedrag Python rekenlaag Canonical data models Bovi-facing API

2. Hoe de Fortran-flow loopt

Dit is de originele route die we porten. De belangrijkste scheiding is dat parsing en output in de main/fmt4 laag zitten, terwijl de numerieke best-predict algebra in bestpred.f90 zit.

3. Hoe de Python-port nu is opgebouwd

De Python-port bootst de Fortran-output bewust na voor validatie. De nieuwe adapter zet FDD identiteit plus tijdelijke lactatie/testdag DTO's om naar dezelfde Format4Record boundary als de file parsers.

4. Welke schema's missen nog?

Hieronder staat wat er in FDD hoort, wat tijdelijk in bestpred-py zit en wat Bovi later als wrapper kan gebruiken.

Concept Status nu Waar hoort het logisch? Prioriteit

5. Logisch eindbeeld

Het eindbeeld is niet dat Bovi alle Fortran-details overneemt. Bovi houdt een eenvoudige API; FDD draagt de data-contracten; bestpred-py voert de officiele multi-trait BESTPRED berekening uit.
